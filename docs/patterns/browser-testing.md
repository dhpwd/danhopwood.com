# Browser testing

## Testing client scripts and functions

**Problem:** behaviours of this site, the browser and Node break the obvious test harness, either failing with an error that points elsewhere or passing when the code is wrong.

**Solution:**

- `global.css` applies `motion-safe:scroll-smooth` to `html`, so after Playwright's `fill()` scrolls down a long post the target keeps moving for about a second, and `click()` fails with "element is not stable". Wait for the scroll to settle before clicking
- `html` is `overflow-y-scroll`, and headless Chromium's scrollbar takes 15px at 390, where a phone's overlays the page. Hide it (`html { scrollbar-width: none }` from an init script) before measuring layout or sideways scroll
- `addInitScript` runs before `<html>` exists, so `document.documentElement.appendChild(style)` there throws, as a `pageerror` rather than a console error, and the style never lands. A scrollbar-hiding script written that way leaves the 15px scrollbar in place. Add the style with `page.addStyleTag` after `goto`, or from a `DOMContentLoaded` listener in the init script
- A context's `colorScheme` picks the theme only while `localStorage` has no `theme` key. A test click on the theme button writes one, and every later page in that context keeps that theme – remove the key after the click. The click also holds the theme until the next full load, so an `emulateMedia` before then changes nothing, even once the key is removed
- To test blocked storage as a real browser blocks it, block all cookies. Launch Firefox with `firefoxUserPrefs: { "network.cookie.cookieBehavior": 2 }`, or Chromium with `launchPersistentContext` and `channel: "chromium"` on a user-data dir whose `Default/Preferences` holds `{"profile":{"default_content_setting_values":{"cookies":2}}}`. Reading `localStorage` or `sessionStorage` then throws a `SecurityError`. The default headless shell ignores the Chromium pref and reads storage as normal, so a check without `channel: "chromium"` passes on code that breaks in a real browser
- A screenshot drops `:hover`, so read a state's computed style while the state is held, between `hover()` or `mouse.down()` and the next mouse move
- A touch screen keeps `:hover` after a tap, but a tap on a link navigates before its style can be read. To read the sticky hover, open the context with `isMobile: true, hasTouch: true`, so `(hover: none)` matches, and hold the state with CDP `CSS.forcePseudoState` after `DOM.enable` and `CSS.enable`. Take every `nodeId` from `DOM.querySelector` on one `DOM.getDocument` root: a second `DOM.getDocument` issues new ids and drops the state forced through the first
- A colour from a `/75` utility or a `color-mix()` token computes with alpha or in another space (`oklab(… / 0.75)`, `color(srgb …)`), which is not the colour on screen. To measure contrast, paint the ground's computed colour and then each layer onto a 1×1 canvas and read the pixel
- On `/search`, clicking Clear empties the results, so test "Load more results" before it
- The fonts API registers each family under a hashed name, so `font-family` computes as `Geist-4350b8f6…` or `Geist Mono-1081b9fc…`. Match the face by prefix, with the hash stripped, not by equality
- `<ClientRouter />` saves the scroll position with `history.replaceState`, which fires Playwright's `framenavigated` on the same URL. To assert that a submit didn't navigate, count navigation requests (`request.isNavigationRequest()`) or check a `window` marker survives, not `framenavigated`
- To hold a page before window `load`, hold the `plausible.io` script request in a `route` handler and fulfil it with an empty body once the check is done. The async script holds back `load`, and an empty body leaves an init-script recorder in place of `window.plausible`. Assert `document.readyState` is `"interactive"` before each early action, so a check can't pass on a page that has already loaded
- To show a handler isn't bound twice, count its node's listeners by type with CDP `DOMDebugger.getEventListeners`, taking the `objectId` from a `Runtime.evaluate` of the selector, rather than counting what the handler does. A second listener on an action that is safe to repeat, such as opening the zoom dialog, changes nothing visible. The same call reads `window` and `document`
- To test a Back or Forward, click a link through the DOM, call `page.goBack()` and compare `scrollY` with its value before leaving, read 1.5s later. To find what moved the page, wrap `window.scrollTo` from an init script and log each call with the first caller line of `new Error().stack`. To catch a glide, push `scrollY` on every animation frame from an `astro:after-swap` listener and read the trace
- To test a scroll that ends while the router fetches the next page, hold the document request with `page.route` and start the smooth scroll and `history.back()` in one `page.evaluate`. A separate `page.goBack()` can land after a short smooth scroll has ended, and the check then passes on code that reads `history.state` too late. The same hold tests a debounced callback that fires while the router fetches, such as Pagefind's 300ms search: on a Back or Forward the URL has already moved to the new entry and the old page is still in place. A local build fetches the next page inside the debounce, so without a hold of 150ms or more the race never shows
- To start a second navigation while the first is mid-swap, start it from an `astro:after-swap` listener. Chromium turns `history.back()` and `history.forward()` called in one task into a single traversal, and a link click straight after `history.back()` is overtaken by the traversal, so a check written that way passes on code without the guard it is meant to test
- playwright-core launches Chromium with `--disable-back-forward-cache`, and its default headless shell refuses a restore from the back/forward cache even with that flag removed (CDP `Page.backForwardCacheNotUsed` reports `BackForwardCacheDisabledForDelegate`). To test a cache restore, launch with `channel: "chromium"` and `ignoreDefaultArgs: ["--disable-back-forward-cache"]`, and read `persisted` from a `pageshow` listener in an init script. A check that doesn't read `persisted` passes on a fresh load
- `location` and `history.state` show only the current entry. To check what a navigation did to another entry, such as the one a Back moved to before the router pushed past it, read every entry's URL before and after with CDP `Page.getNavigationHistory`
- To make an entry the router doesn't track, `page.goto` the current URL plus a `#hash`. Like a hash typed in the address bar, it is a fragment navigation the router doesn't handle, and the new entry's `history.state` is `null`. Read the router's index with `Number.isInteger(history.state?.index)`: `JSON.stringify` prints `NaN` as `null`, so a logged state can't tell a corrupted index from a missing one
- `pnpm astro preview` serves `_astro/` with `Cache-Control: no-cache`, so WebKit requests the web fonts again after a client-side swap, and the router restores a Back or Forward onto a page still set in the fallback font. A title above the restored position that wraps there moves it by a line when the fonts arrive. With `_astro/` cached as production serves it (`immutable`), WebKit requests no fonts and nothing moves. To test a restore in WebKit, serve the build from a static server that sends `_astro/` with `Cache-Control: public, max-age=31536000, immutable`
- `locator.ariaSnapshot()` prints a toggle's `[pressed]` only when it is true and omits it when false, so a missing `aria-pressed` and `"false"` read the same. Read `getAttribute("aria-pressed")` to tell them apart
- Submit forms by clicking the button as well as pressing Enter in a field. Only the click leaves focus on the button, so a bug in how the handler treats focus shows on that route alone
- `locator.boundingBox()` is relative to the viewport, and a click can scroll the page. To assert an element didn't move, compare `getBoundingClientRect().top + scrollY`
- A control's state changes over the shared 150ms, so a computed style read straight after `focus()` or `hover()` is the start of the transition – a field's focus ring reads as transparent. Wait past the duration before reading
- A full-page screenshot clipped to an element far below the viewport can show a post image as an empty box, even after it has loaded. Scroll the element into view and `await img.decode()` before the screenshot. Post images are `loading="lazy"`, so set them eager first
- An element inside a closed `<details>` still returns its laid-out box from `getBoundingClientRect()`, since Chromium hides the content with `content-visibility` rather than `display: none`. Read `checkVisibility()` to tell whether it shows
- `locator.ariaSnapshot()` gives a `summary` no role, so a disclosure's control and its expanded state are missing from it. Read Chromium's own role, name and `expanded` with CDP `Accessibility.getPartialAXTree` on the `summary`'s `nodeId`
- `textContent` runs a link's flex items together ("ai17 posts"). Read what a screen reader announces from `locator.ariaSnapshot()`, which separates them
- `pnpm preview` answers a path with a trailing slash (`/about/`) with the 404 page – see `docs/patterns/urls.md`. A check that queries the page then finds nothing and passes, so write test URLs without the slash
- A position read from a screenshot's pixels, such as where a marker's ink starts, can differ by a pixel between Chromium builds and scale factors. Compare before and after in the same browser at the same scale
- To compare an element pixel for pixel across two builds, hide the site header on both. A change in the header's height moves everything below it by a fraction of a pixel, which changes its anti-aliasing and reads as a difference
- Headless Chromium on `localhost` writes to the clipboard without a permission grant, so an unstubbed copy test passes whatever the page does when a write fails. Replace `navigator.clipboard.writeText` from an init script to test the failure path, and grant `clipboard-read` to read the clipboard back after a real write
- Node's `AbortSignal.timeout` timer doesn't keep the event loop alive. A stubbed `fetch` that hangs until aborted needs its own pending timer, or the test script exits before the timeout fires
- `astro dev` and `astro preview` move to the next free port when the one passed to `--port` is taken, and say so only in their output ("Port 4391 is in use, trying another one..."). Read the port from the server's "Local" line before sending requests. A request to the port you asked for reaches another session's server, and its 404s read as yours
- A state that a page timer resets, such as the Copy button's "Copied", can be gone before a screenshot lands. Install `page.clock` before `goto` and call `pauseAt` once the page has loaded: after that no page timer fires until `runFor`, so the state holds while you screenshot it. `install` alone leaves time running, and the timer fires on schedule. To read a value at a set time after a click, schedule the read in the page with `setTimeout` from a capture-phase `click` listener, rather than waiting in Playwright, whose round trips add tens of milliseconds. A `MutationObserver` that logs each change with `performance.now()` gives the actual timings to compare across two builds
- A screen recording in real time stutters under load. To record motion, install `page.clock` and `pauseAt`, then for each 33ms frame `runFor` 33ms, advance every animation in `document.getAnimations()` by hand and take a CDP screenshot. A phone profile with CDP touch events does draw the tap flash
- To check view-transition motion under reduced motion, open the context with `reducedMotion: "reduce"` and record every `document.getAnimations()` entry whose `effect.pseudoElement` starts with `::view-transition`, every few milliseconds from before the click until after the swap
- A build run with `pnpm astro build --outDir <dir>` also leaves Astro's own files in `<dir>` (`content-assets.mjs`, `content-modules.mjs`, `collections/`, `fonts/`), which `pnpm run build`'s `dist/` doesn't hold. They can differ between two builds of the same source (a fonts cache expiry, the order of image imports), so leave them out of a build diff. Two build trees, each with its own fonts cache, can also point a face's `@font-face` and preload at different hashed files, which changes every page's HTML. Replace `/_astro/fonts/<hash>.woff2` with a placeholder in both before comparing pages
- Built pages are minified onto a few long lines, inline scripts included, so a line diff of two builds shows whole pages as changed. Split both at `<`, `>`, `;`, `{` and `}` onto separate lines first, then diff
- An element with `transition:name` or `transition:persist` carries `data-astro-transition-scope="astro-<id>-<n>"`, and the page's inline view-transition `<style>` selects on it. The compiler derives `<id>` from the component's template, so some edits to the component rename it on every page that renders it, with the selectors renamed to match. Adding or removing an element or an expression ahead of the transition element renamed it. Elements added after it, and attribute, frontmatter and `<script>` edits, didn't (`@astrojs/compiler` 2.13.0). In a build diff, confirm a renamed scope changes nothing by reading the element's computed `view-transition-name` in both builds, rather than counting the rename as a change
- An edit to `search.astro`'s `<script>` also renames `_astro/ui-core.<hash>.js`, Pagefind UI's chunk, with its code unchanged. It imports Vite's preload helper from the search script's chunk, so its first line names that chunk's new hash. Only the search chunk loads it, so in a build diff it is one of search's chunks, not a shared one. Confirm by splitting both copies at `;` and `,` and diffing: only the import line differs
- To check a diagram's connectors at 1x, 2x and 3x (step 4 of "Checking a diagram" in `docs/patterns/diagrams.md`), open a context per scale with `deviceScaleFactor` and save the figure with `locator.screenshot({ path, scale: "device" })`. The Playwright MCP's `browser_run_code` has no `require()`, so read the pixels in a second page instead: load the PNG as a data URL into a canvas and scan each band. Across a horizontal line, every column must hold exactly as many pixels within a few levels of `--dg-wire` (composited onto the ground, as for contrast) as the scale factor, at the same rows all along the band, and likewise down a vertical line. No pixel may sit further from the ground than the wire colour, or a junction has darkened. To enlarge a crop, draw it onto a canvas with `imageSmoothingEnabled = false` and screenshot that canvas. Read where a line meets a dashed frame from the border row's pixels: a line can end in a dash gap that the boxes' positions don't show
- To check where a thin line paints against text, such as the line of ink against the dashes, measure it at every position its baseline can take within a pixel, not on one page. The line and the text decoration snap to the pixel grid separately, so a rule that holds at one position can be a pixel off at another. Lay the cases out in normal flow, as a grid over the page whose cells' `padding-top` steps the baseline through a pixel in 1/32px steps: cells positioned inside a `position: fixed` overlay snap together and hide the difference. Read each baseline from a zero-size `inline-block` probe appended to the text, force the hover state with a class that repeats the hovered declarations under `!important` with transitions off, and shoot the viewport with `scale: "device"` at 1x, 2x and 3x. For any scale above 1x, launch Chromium with `--force-device-scale-factor=<n>` as well as setting the context's `deviceScaleFactor`: the context setting alone scales the screenshot but not how Chromium rounds font metrics and snaps text, so a 2x or 3x pass there matches 1x and misses what a high-density screen shows. Shoot each cell four ways: the dashes alone, the line alone, both and neither. The pass criterion is that, with the line drawn and the dashes still showing, no dash ink shows outside the line's rows. Take the line's rows from the line-alone shot, then, per cell, sum what the dashes add to the line alone in the rows outside them, as a share of the dashes' own ink over the ground. That share, the dash ink left visible, must be 0. Inside the line's rows a translucent line darkens where a dash crosses it, which is not a miss. A line whose rows sit inside the dash rows isn't enough, since a 1px line inside a 1.5px band leaves a third of it showing. To see where each paints, list the rows where enough of the cell's width differs from the ground: 30% for dashes, 80% for a solid line. On a real page, start the clip on a device pixel (`Math.floor(y * dpr) / dpr`) so the offsets are exact to one. A result in Chromium doesn't carry to Firefox, which rounds differently
- A `console.log` in build-time code can print on the same line as Astro's route listing (`└─ /index.htmlMARKER …`). To count how often a module or function runs in a build, count every match (`grep -o MARKER build.log | wc -l`), not lines that start with the marker

Run Playwright against `pnpm build && pnpm preview`. To compare a base and a change, copy each build's `dist/` aside and serve both at once with `pnpm astro preview --port <port> --outDir <copy>`, on ports other sessions aren't using. Stub `api/` routes with `page.route` (preview doesn't serve them), and test a function by calling its default export's `fetch` from a Node script with a stubbed global `fetch`.

**When to use:** browser-testing a client script or a change to what a page renders, testing an `api/` function, or checking build-time code with a temporary log.
